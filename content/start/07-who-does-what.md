# Who does what

A person in an organization is an **admin here**, an **admin for the whole account**, or a **member with limited access** made of presets. Presets cover an area across the organization; they do not limit someone to one task, agent, or skill. Every console page in this documentation says which access it needs.

| Preset | Lets the person | Pages |
| --- | --- | --- |
| Task observer | Read task standards, comparisons, and live results | [The standard](/console/tasks/the-standard), [Compare and release](/console/tasks/compare-and-release) |
| Skill contributor | Read skills, import packages, and save drafts | [Shared skills](/console/skills/shared-skills) |
| Skill manager | Create, publish, and retire skills | [Shared skills](/console/skills/shared-skills) |
| Agent observer | Inspect agent runs, steps, and permission decisions | [Agent rules and limits](/console/agent-runs/agent-rules) |
| Agent operator | Set up agents, inspect runs, and save steps for review | [Connect](/console/connect/connect), [Agent rules and limits](/console/agent-runs/agent-rules) |
| Agent permissions manager | Inspect runs and change tool rules and limits | [Agent rules and limits](/console/agent-runs/agent-rules) |
| Agent approver | Review held actions and approve or reject them | [Approvals](/console/inbox/approvals) |
| Reviewer | Review labels, saved steps, and proposed corrections | [Live answers and corrections](/console/tasks/live-answers-and-corrections) |
| Evidence auditor | Read recorded history and metadata without changing work | [Evidence](/console/evidence/evidence) |

Admins can do all of this and also manage people, keys, provider credentials, models, and notifications under [Settings](/console/settings/people-keys-and-notifications). Access can carry an expiry date, and every change to it is recorded.

Runtime keys are for applications and agents, not people: they carry scopes, and some actions are never available to a key. See [Sign up and create a key](/start/sign-up-and-keys).
